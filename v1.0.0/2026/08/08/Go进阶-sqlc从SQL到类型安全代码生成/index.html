Go 进阶：sqlc 从 SQL 到类型安全代码生成

平时使用 database/sql 写 CRUD 时，SQL 本身并不难，真正麻烦的是 SQL 之外的大量重复代码：定义结构体、传递参数、调用 QueryContext()、逐个 Scan() 字段，再一层层处理错误。

sqlc 提供了另一种思路：SQL 由开发者编写，重复的 Go 数据访问代码交给工具生成。

一句话理解 sqlc：

把数据库结构和 SQL 查询交给 sqlc，它会生成可以直接调用的、类型安全的 Go 代码。

本文以 PostgreSQL 为主，同时给出 MySQL 的关键区别。

二、sqlc 的核心思想：SQL-to-Code

sqlc 的思想不是隐藏 SQL，而是把 SQL 当作代码生成的输入：

也就是说：

  • SQL 怎么写，由开发者决定。
  • SQL 是否符合 schema，由 sqlc 在生成阶段检查。
  • 参数、返回结构体、Query() 和 Scan() 等代码，由 sqlc 生成。
  • Go 业务层直接调用生成的方法。

它不是传统 ORM，也不会要求我们把查询改写成链式 API。

三、sqlc 的工作流程

    flowchart LR
    A["1. schema.sql<br/>定义表、字段和约束"] --> B["2. sqlc.yaml<br/>指定数据库和输出目录"]
    B --> C["3. query.sql<br/>编写带标记的业务 SQL"]
    C --> D["4. sqlc generate<br/>分析并生成代码"]
    D --> E["5. Go Package<br/>结构体和查询方法"]

整个过程可以记成五步：

  1. 在 schema.sql 中描述数据库结构。
  2. 在 sqlc.yaml 中告诉 sqlc 去哪里读取、生成到哪里。
  3. 在 query.sql 中编写真实 SQL。
  4. 执行 sqlc generate。
  5. 在业务代码中调用生成的 Go 方法。

五、MySQL 怎么写

sqlc 同样支持 MySQL，整体流程完全一样，主要区别在数据库方言。

1. MySQL 的 schema.sql

2. MySQL 的 sqlc.yaml

3. MySQL 的 query.sql

PostgreSQL 和 MySQL 的关键差异：

项目 PostgreSQL MySQL
配置引擎 postgresql mysql
参数占位符 $1、$2 ?
自增主键 BIGSERIAL 或 Identity AUTO_INCREMENT
插入后返回记录 常用 RETURNING ... 常用 :execresult 获取结果

不要在同一个查询文件中混用 $1 和 ?。SQL 必须符合当前配置的数据库方言。

六、sqlc 和 GORM 有什么区别

GORM 是 Go 生态中常用的全功能 ORM，而 sqlc 更接近 SQL 代码生成器。两者解决问题的方向不同。

对比 sqlc GORM
核心思想 SQL-to-Code Struct / API-to-SQL
查询写法 手写原生 SQL 使用 Go 链式 API
SQL 控制力 高 常规 CRUD 更方便
类型代码 根据 SQL 和 schema 生成 主要围绕模型结构体运行
动态查询 需要自己组织方案 链式拼接更方便
学习重点 SQL 和生成规则 ORM API 和模型关系

可以这样记：

sqlc 比较适合：

  • 希望保留原生 SQL 控制力。
  • 查询较复杂，需要准确掌握执行内容。
  • 希望减少 Scan() 和结构体映射代码。
  • 希望通过生成代码获得更明确的参数和返回类型。

GORM 比较适合：

  • CRUD 占比高。
  • 需要快速开发。
  • 动态条件和关联操作较多。
  • 团队更熟悉 ORM 的使用方式。

它们不是绝对的谁替代谁，而是两种不同的数据库开发方式。

七、使用 sqlc 时要注意什么

1. 不要手改生成代码

internal/db 中的生成文件再次运行 sqlc generate 后可能被覆盖。需要修改查询时，应修改 schema.sql、query.sql 或 sqlc.yaml。

2. schema 要与真实数据库保持一致

sqlc 根据 schema 生成类型。如果 schema 文件与线上数据库不一致，即使 Go 代码可以编译，运行时仍然可能出错。

3. sqlc 不负责数据库迁移

sqlc 负责分析和生成代码。建表、升级字段和回滚版本，仍然需要迁移工具或团队自己的迁移流程。

4. 动态查询不是 sqlc 的强项

当筛选条件需要任意组合时，纯静态 SQL 会变得复杂。这类场景可以拆分固定查询、配合查询构造器，或者评估 ORM 是否更合适。

八、一句话复盘

最终理解：sqlc 没有让我们忘记 SQL，而是让我们专心写 SQL，同时把重复、容易出错的 Go 数据库样板代码交给生成器。
