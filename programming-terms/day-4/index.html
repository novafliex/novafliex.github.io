安全、连接与实时通信

HTTPS 依靠 TLS 保护通信｜Keep-Alive 复用连接｜CORS 控制跨域｜WebSocket 支持双向通信

今天的 5 个术语，可以放进下面这张关系图中：

HTTPS（超文本传输安全协议）

正式解释：

HTTPS 是运行在 TLS 安全通道之上的 HTTP，用于保护客户端与服务器之间传输的数据。

通俗理解：

给 HTTP 套上一层 TLS 安全外壳。传输中的 HTTP 内容会被加密并检查有没有遭到篡改，所以通信更安全。

项目例子：

当客户端访问 https://api.example.com/courses 时，请求内容会通过 TLS 加密后再传输。HTTPS 的默认端口通常是 443。

TLS（传输层安全协议）

正式解释：

TLS 是一种用于保护网络通信的加密协议，可以提供身份认证、数据机密性和数据完整性。

通俗理解：

TLS 是一套完整的安全协议——它不仅提供加密手段防偷看，还顺便把**身份验证（防冒充）和完整性校验（防篡改）**全给办了

项目例子：

浏览器访问 HTTPS 网站时，会在发送 HTTP 数据前与服务器进行 TLS 握手，并验证服务器证书。握手成功后，双方使用协商出的密钥加密后续通信。

Keep-Alive（持久连接）

正式解释：

Keep-Alive 是复用底层网络连接处理多个请求与响应的机制，可以减少重复建立连接带来的开销。

通俗理解：

打通电话后先别挂，有事接着说，省得每次都重新拨号

Tips：Keep-Alive 能保持多久？

Keep-Alive 连接能空闲多久，通常由 Web 服务器或 Nginx、CDN 等网络代理的超时配置决定，也可能受到客户端超时设置的影响。

CORS（跨源资源共享）

正式解释：

CORS 是一种基于 HTTP Header 的浏览器安全机制，服务器通过响应头声明哪些源可以跨域访问自己的资源。

通俗理解：

浏览器为了防坏人，默认不让你跨门串户；但如果对方主人贴了通行许可，浏览器就放行。

项目例子：

对于某些跨域请求，浏览器会先发送 OPTIONS 预检请求，确认服务器允许后再发送正式请求。

WebSocket（全双工通信协议）

正式解释：

WebSocket 是一种在单个长连接上进行全双工通信的应用层协议，客户端和服务器都可以主动向对方发送数据。

通俗理解：

传统 HTTP 更像一问一答：客户端先问，服务器再回答。WebSocket 更像实时通话，连接建立后，客户端和服务器谁有消息都可以主动发送。

项目例子：

升级成功后，客户端与服务器可以在同一条连接上持续双向发送消息，不需要为每条消息重新发送一次普通 HTTP 请求。

Tips：HTTP 请求—响应与 WebSocket 的核心区别

维度 HTTP 请求—响应（通常由客户端发起） WebSocket（全双工）
通信模式 一问一答：客户端先发起请求，服务器再针对该请求返回响应。 随时双向互通：长连接建立后，客户端和服务器都能主动发送数据。
生活比喻 像在餐厅按铃叫服务员，按一次处理一次。 像两个人实时语音通话，双方随时都可以开口。
实时方案 通常使用轮询、长轮询或 SSE 等方式获取最新消息。 服务端有新消息时可以直接推送，适合聊天、通知等实时场景。
网络开销 每次请求和响应通常都需要携带 HTTP Header。 握手完成后使用较轻量的数据帧传输，但实际开销取决于帧长度、掩码和扩展。
